## M02 · 共享文件加 env.mode 用了 location 导致 node 单测沙箱报错（2026-10-09）
**现象**：为收口形态判定，在 `js/01-utils.js` 加 `WB.env.mode`，其中写 `location.protocol === "file:"` 判文件夹版。`npm test` 全线报 `ReferenceError: location is not defined`（`tests/store-security.test.mjs` 用 `node:vm` 加载 01-utils.js）。
**原因**：测试沙箱只 mock 了 `window`/`localStorage`/`document` 等，**没有 `location`**。浏览器里 `location` 是全局对象，但 `node:vm` 沙箱里裸引用 `location` 直接抛 ReferenceError —— 和 `__WB_APP__` 的 `typeof` 兜底同理，`location` 也必须防御。
**解法**：`if(typeof location !== "undefined" && location.protocol === "file:") return "folder";`（`typeof` 对未定义标识符返回 `"undefined"`，不抛错）。
**教训**：改 `js/` 下任何共享文件（00–19 前缀、01-utils 等）时，要记住它们会被 `node:vm` 沙箱加载跑单测。**浏览器全局（location / Notification / document 等）一律用 `typeof` 或 `window.` 防御**，否则第一次 `npm test` 就崩。这是「App 改动不能影响网页端/测试」这条铁律在测试层的一个具体落点。
**现象**：`gradlew.bat assembleDebug` 报 `Your project path contains non-ASCII characters. This will most likely cause the build to fail on Windows`，`Failed to apply plugin 'com.android.internal.application'`。
**原因**：项目根路径 `c:/Users/echo/Desktop/diy/vibecoding/个人工作台` 含中文目录名。Android Gradle Plugin（AGP 8.x）在 Windows 上默认对非 ASCII 路径做硬校验，直接拒绝评估 `:app` 工程。与根项目踩坑 #019–#023「npm 中文目录」同源。
**解法**：在 `mobile/android/gradle.properties` 加 `android.overridePathCheck=true`（官方在报错里给出的开关）。
**教训**：① Windows + 中文路径是 Android 构建的第一道拦路虎，`cap add android` 能生成、`cap sync` 能过，**唯独 gradle 真正评估工程时才炸**——所以「生成成功」≠「能构建」，必须跑到 `assembleDebug` 才算数。② 现代 AGP 8.x 加开关后中文路径实测可正常构建，无需迁目录；但若未来遇到 AAPT/资源合并的诡异报错，先怀疑路径字符再怀疑代码。
